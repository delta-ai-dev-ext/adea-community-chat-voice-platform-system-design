## What this is

A real-time community platform: invitation-only communities, text channels, voice
and video rooms over LiveKit Cloud, direct and group conversations, and moderator
tooling with roles, sanctions, an audit log and appeals.

Eight Go services, each a stateless container, communicating over Kafka and a
small set of internal REST contracts.

## The contract-first approach

This is the part worth reading if you want to understand why the implementation
came out coherent. Before any service was written, every edge in the system was
pinned to a numbered contract.

**Synchronous edges** are numbered `API-001` … `API-003`. Each one names a
provider, its consumers, the exact operation, and a JSON Schema for the request
and response. Internal endpoints live under `/internal/*`, are never exposed
through the public ingress, and authenticate with a per-edge service token.

**Asynchronous edges** are numbered `EVT-001` … `EVT-011`. Every event on every
topic carries the same mandatory envelope:

```json
{
  "envelope": {
    "event_id": "…",          // consumer deduplication key
    "event_type": "…",        // must match a registered contract
    "event_version": 1,       // a breaking payload change bumps it
    "occurred_at": "…",       // RFC3339 UTC, producer clock
    "producer": "…",          // must equal the registered producer
    "trace_id": "…",          // never empty, minted at the edge when absent
    "correlation_id": "…",    // groups every event of one business flow
    "causation_id": "…",      // event_id of the causing event
    "schema_ref": "…"         // EVENT_CONTRACTS.md#<event_type>-v<version>
  },
  "payload": { }
}
```

Three rules make this hold together:

- **The envelope is not optional and not per-topic.** A topic needing a field the
  envelope lacks adds it to `payload`, never to the envelope.
- **`trace_id` is mandatory even when no HTTP request started the flow.** Scheduled
  jobs, LiveKit webhooks and audit purges mint one at their own edge. A consumer
  emitting an event because of another event copies `trace_id` and
  `correlation_id` and sets `causation_id` to the causing `event_id`.
- **Delivery is at-least-once.** Every consumer dedupes on `envelope.event_id` and
  applies changes idempotently; projections keep an entity version and ignore
  stale versions.

The payoff is that a service can be implemented, reviewed and tested against a
contract that already exists, rather than discovering the contract by reading
another service's code.
